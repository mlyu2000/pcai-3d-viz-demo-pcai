# Viz Demo (PCAI 3D Viz PoC) — Blender Add-on

Single-file Blender 4.x / 5.x add-on (Python 3.11+, **stdlib only** — no `openai`, no
`requests`; the LLM call uses `urllib.request`). Two tiers:

- **Tier 1 — Load Blender Pack** (deterministic, no LLM, guaranteed demo path):
  pick the unzipped *blender-pack* folder → the add-on runs `scene.py` →
  a textured **cup** (albedo + height-relief variants) appears in the viewport
  and a `.blend` is saved.
- **Tier 2 — AI Model Box** (optional iteration): prompt → generated `bpy`
  code → safe-check → exec in Blender → **auto-retry ×3** on error, against an
  OpenAI-compatible endpoint (CS1 LiteLLM or local Ollama).

---

## 1. Install (Blender 4.x or 5.x)

1. Edit → **Preferences** → **Add-ons** → **Install…**
2. Select `viz_demo_addon.py`
3. Enable **Viz Demo (PCAI 3D Viz PoC)**
4. Open a 3D View and press **N** (top-right of the 3D view) → sidebar →
   **"Viz Demo"** category. You'll see the *Load Blender Pack* panel and the
   *AI Model Box* panel.

> The add-on is written against the Blender 4.x Python API
> (`bl_space_type='VIEW_3D'`, `bl_region_type='UI'`, `bl_category`,
> `AddonPreferences` with `bl_idname = __name__`, `StringProperty(subtype='DIR_PATH')`).
> It requires Blender ≥ 4.0 (`blender = (4, 0, 0)` in `bl_info`) and is
> **version-robust across 4.x and 5.x** — `register()`/`unregister()` are
> idempotent and the generated `scene.py` picks the correct displacement API
> per version. Verified end-to-end in **Blender 5.2.2 LTS** (headless).

---

## 2. Tier 1 — Load Blender Pack

**Where to get the pack:** in the demo web UI, click **"Download Blender-pack"**
on an asset (or the library row) → you get `<id>-blender-pack.zip`.

1. **Unzip** the file to any folder (e.g. `Downloads/marble-01-blender-pack/`).
   It contains: `albedo.png`, `height.png`, `normal.png`, `roughness.png`,
   `metallic.png`, `scene.py`, `README.md`, `ca/ezaf-aie-root-ca.pem`, and —
   when the asset has image-derived 3D — `model.obj`.
2. In Blender: 3D View → **N** panel → **Viz Demo** → *Load Blender Pack*:
   - **Pack folder**: click the field → browse to the **unzipped** folder
     (the one that directly contains `scene.py`).
   - Click **Load Pack**.
3. The add-on validates the folder (`scene.py` + `albedo.png` + `height.png`),
   execs `scene.py` with `__file__` set to the absolute path of `scene.py` (so
   the script finds its own maps), then verifies the `.blend` was saved and
   reports its path in the status line and the header.

**The `.blend` is generated by Load Pack** — it is NOT inside the zip. After
the run you get two objects in the viewport — `*_Albedo` (full PBR material)
and `*_Relief` (PBR + height-map Bump) — and an `<asset_id>.blend` saved next
to the maps. When `model.obj` is present the object is the **image-derived
3D mesh**; otherwise it is the procedural shape (cup/dog/wood).
**No LLM involved; guaranteed demo path.**

*Headless alternative (no add-on):* from the unzipped folder run
`blender --background --python scene.py` (the `--python` flag is required —
without it Blender treats the .py as a document to open).

## 3. Tier 2 — AI Model Box (LLM modeling)

Configure the endpoint once, then type prompts into the *AI Model Box* panel
and click **Generate (LLM)**. The last status (success / error / attempt count,
truncated error) shows under the button.

### 3.1 Configuration (Edit → Preferences → Add-ons → **Viz Demo (PCAI 3D Viz PoC)**)

| Field | CS1 (default target) | Local Ollama (fallback) |
|---|---|---|
| **Base URL** | `http://localhost:4001` (port-forward) **or** `https://litellm.aie.cs1.ctc.sg.lab/v1` | `http://localhost:11434/v1` |
| **Model** | `qwen3-8-27b-int4-dflash2-r2` | `qwen2.5-coder:7b` |
| **API Key** | the **API key** from `key.txt` in the pack (a scoped LiteLLM **virtual key**) | `ollama` (any non-empty string) |
| **CA Bundle (TLS)** | *(port-forward: empty)* / *(ingress: `ca/ezaf-aie-root-ca.pem` from the pack)* | *(leave empty)* |

**CS1 — two working paths (both verified with a live chat completion, HTTP 200):**

1. **Port-forward (simplest — no TLS, no CA, no kubectl secret fetch):**
   - Run once in a terminal:
     `kubectl -n project-user-aieadmin port-forward svc/litellm-helm 4001:4000`
   - Base URL `http://localhost:4001`, Model `qwen3-8-27b-int4-dflash2-r2`,
     API Key `the API key (see the 'key.txt' note below)`, **CA Bundle empty** (plain HTTP).
   - This is exactly how the HPE solution-architect Hermes agent on the CS1
     platform talks to the same model (its `config.yaml` uses `http://localhost:4001`
     + the `the API key (see the 'key.txt' note below)` virtual key), so it is a proven, working connection.
2. **Public ingress (no kubectl, but needs the CA):**
   - Base URL `https://litellm.aie.cs1.ctc.sg.lab/v1` (pre-wired in the Istio
     gateway `istio-system/ezaf-gateway`), API Key `the API key (see the 'key.txt' note below)`,
     **CA Bundle** = `ca/ezaf-aie-root-ca.pem` from the pack (the ingress cert is
     signed by the private "HPE Ezmeral AIE Root CA", which Windows does not
     trust → without the CA you get `CERTIFICATE_VERIFY_FAILED`).

**Model id**: exactly `qwen3-8-27b-int4-dflash2-r2`. It is a **reasoning model**
— each generation can take ~40–90s; the add-on's timeout is 90s, so just wait
for the status line.

**Why a virtual key, not the master key:** `the API key (see the 'key.txt' note below)` is a scoped
LiteLLM virtual key already registered in the proxy — individually revocable and
auditable, so you never hand the artist the global master key
(`litellm-helm-masterkey`). The master key still works if you prefer it; the
virtual key is the safer default.

**Local Ollama fallback** (if the workstation cannot reach the CS1 ingress):
install [Ollama](https://ollama.com), run `ollama pull qwen2.5-coder:7b`,
leave the defaults (`http://localhost:11434/v1` / `qwen2.5-coder:7b` / `ollama`,
CA Bundle empty).

### 3.2 Example prompts (for the live demo)

- `add a stone pedestal under the object`
- `make the surface relief stronger` (raises the Bump strength)
- `add a point light above the object`

The system prompt tells the model to output only a single ```python block,
never delete existing objects unless asked, and use image texture nodes for
textures. On an exec error the traceback is fed back (`Fix the error in this
Blender code: …`) for up to **3 total attempts**.

## 4. Security note — read before the demo

The generated code is **exec'd inside Blender**. The safe-check blocklists
`os`, `subprocess`, `shutil`, `socket`, `ctypes`, `pickle`, `http`, `urllib`
(import statements **and** bare/dotted references, e.g. `os.system`) — but this
is a **guardrail, not a sandbox**:

- Code that passes the check still runs with full Blender privileges and can
  modify the local scene, materials, camera, and save/render files under
  Blender's own paths.
- An LLM can be (or be induced to be) creative around a simple blocklist.
  For the PoC this is acceptable: the add-on runs on the artist's own
  workstation against the artist's own scene, with no other users involved.
- If you extend this beyond the PoC, add an AST-level allowlist, run the code
  in a subprocess, or review each generated script before exec.

## 5. Troubleshooting

| Symptom | Fix |
|---|---|
| `Pack folder is missing required file(s)` | You picked the zip or a parent folder — select the folder that **directly contains `scene.py`**. |
| `LLM endpoint not configured` | Set Base URL + Model in add-on preferences (Section 3.1). |
| `LLM call failed (attempt …): <urllib error>` | Endpoint unreachable / wrong host / network policy — try the Ollama fallback. |
| `CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate` | CS1 TLS cert is signed by the private HPE Ezmeral AIE Root CA. Set **CA Bundle (TLS)** to `ca/ezaf-aie-root-ca.pem` from the pack (Section 3.1), or install it into the OS trust store. |
| `LLM call failed (attempt …): timed out` | The CS1 model is a reasoning model — a generation can take ~40–90s. Wait for the status line; the timeout is 90s. If it still times out, check the model is actually serving (`/v1/models`). |
| Generated code does nothing | Check the status line: safe-check rejections and exec errors are shown (truncated). Rerun with a more explicit prompt. |
| No *Viz Demo* tab in the N-panel | 3D View → N → check the add-on is enabled; the category is literally named "Viz Demo". |
